# Deploy Colophon

For full Windows/PowerShell instructions, use [DEPLOYMENT_GUIDE.md](DEPLOYMENT_GUIDE.md). This shorter document is the original implementation handoff; the current manual-deployment status is recorded in [AUTOMATED_DEPLOYMENT_REPORT.md](AUTOMATED_DEPLOYMENT_REPORT.md).

## Vercel: immediately usable local-storage demo

1. Import `https://github.com/Kanishk-Rungta/Colophon` into Vercel.
2. Use the Next.js preset, repository root `.`, Node.js **24.x**, install `npm ci`, build `npm run build`. Keep the default Next.js output directory.
3. Leave all Supabase and AI variables empty for the fully working browser demo. No account creation or API key is required for judges.
4. Deploy. Open the actual generated HTTPS URL and complete the judge workflow before submitting it.
5. Verify `/api/health` reports `mode: local`. It intentionally does not claim a database connection.

No Vercel token, project, or deployment authentication was supplied during implementation. No public URL is claimed in this repository until verified. The local demo can be deployed without Supabase; its persistent data remains in each visitor's browser.

## Optional Supabase persistence

1. Create a dedicated Supabase project.
2. Run `supabase/migrations/001_workspace.sql` in SQL Editor once, or use `supabase db push` after linking the project. The migration creates workspace state, membership, action limits, RLS, initialization RPC, and append-only-history trigger. The seed is generated by `lib/seed.ts` for each session, not inserted into one global mutable workspace.
3. Under Authentication → Sign In / Providers, enable **anonymous sign-ins**. Do not confuse the public `anon` project key with an anonymous signed-in user: that user has the `authenticated` database role.
4. Set the Site URL to the deployment's HTTPS origin. Add the local URL only for development. No email confirmation flow is used by this demo.
5. Add `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` to Vercel. The service-role key is a server secret. Redeploy after setting public variables.
6. Keep the migration's client write restrictions. Do not add public insert/update policies to make errors disappear. Review Supabase anonymous-auth rate limits. For a public event, enable recommended bot protection and integrate its CAPTCHA token before turning CAPTCHA on; that extra UI is not implemented here.
7. Verify health reports `hosted`. Each new anonymous user is provisioned with a workspace and creator/reviewer/admin roles to support both sides of the judge journey. Roles come from `workspace_members` and are checked server-side. No claim is made that these represent separate people.

An incomplete set of Supabase variables blocks startup with a configuration error. The app never silently writes browser-local state when hosted persistence fails. Existing local data remains at its previous key; it is not automatically imported or erased.

## Hosted acceptance checklist (external credentials required)

These checks were **not executed against a real database** during development:

- Open two fresh browser contexts; confirm distinct users, memberships, and workspace IDs.
- As context A, query context B's workspace ID with the public client: expect no rows under RLS.
- Attempt direct writes as authenticated/public clients: expect permission denied.
- Remove reviewer role from A's membership in SQL; the API must reject A's decision with HTTP 403.
- Use two tabs to submit the same workspace revision: only one mutation should succeed; the other returns 409.
- Confirm duplicate initialization creates no extra workspace.
- Approve a clean revision; edit the new draft and confirm the SQL-protected old version, publication record, and audit prefix cannot be rewritten.
- Expire an applicable source after scan; approval must require changes and a fresh scan.
- Execute 61 actions in one minute; confirm the rate limit returns 429.
- Restart/deploy the server; previously saved state must still load from Supabase.

## Optional hosted AI

Set server-only `AI_PROVIDER=openai`, `AI_API_KEY`, and `AI_MODEL`. Select a model available in your account supporting strict JSON Schema for Chat Completions. No model name is fabricated or assumed. Hosted scans call it; local browser scans never transmit draft bodies. Missing config skips it; timeout or invalid output leaves deterministic checks intact. Judge access must not depend on provider availability.

## Operations and limitations

Use fictional data only until live security testing is complete. Review database backups, retention/cleanup of anonymous users, costs, quotas, and privacy obligations before a real organization uses this product. For Round 2 the versioned JSONB aggregate minimizes infrastructure, but growing histories should be normalized for a larger product.

Do not submit a placeholder URL. Update `docs/ROUND2_SUBMISSION.md` only after opening and verifying the actual public deployment.
